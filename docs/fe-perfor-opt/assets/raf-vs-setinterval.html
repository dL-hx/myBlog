🎬 requestAnimationFrame vs setInterval

同一个“方块向右移动”的需求，用两种方式各跑一条赛道。
打开控制台切到 Performance / 渲染面板，或干脆把标签页切到后台再切回来，差别一眼就懂。

赛道 A：requestAnimationFrame 推荐

rAF
位置：0 px 速度：0 状态：空闲

赛道 B：setInterval(16ms) 老写法

INT
位置：0 px 定时器ID：- 状态：空闲

🧠 三种“循环”写法对照

① rAF 自己调自己（本例赛道 A）
function tick(){ update(); rafId=requestAnimationFrame(tick); }
帧驱动：浏览器说“该画了”才执行。
② setInterval 定时硬怼（本例赛道 B）
timer=setInterval(()=>update(),16)
时间驱动：16ms 到点就跑，不管画没画完。
③ CSS transition（声明式）
.box{transition:2s}.fly{transform:translateX(300px)}
只加类名，浏览器自己算中间帧，最省心。
刹车方式
rAF → cancelAnimationFrame(id)
INT → clearInterval(id)
CSS → 移除类名 / 改 transition: none

💡 体验技巧：点「一起起飞」后把标签页切到后台挂几秒再切回来。
赛道 A 会停在离开时的位置（后台不跑），赛道 B 的定时器照样在攒，切回来会“跳帧狂奔”。这就是 rAF 更省资源、更稳的原因。
