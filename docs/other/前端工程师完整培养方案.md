# 前端工程师完整培养方案（全栈版）

> 目标：培养一名**对标中大厂资深档位的真正前端全栈工程师**——不只是会 React 写页面，而是从语言基础、浏览器与网络、框架与状态、工程化、Node 服务端、性能与安全，到架构设计与团队影响力，完整走通"前端全栈"的每个能力域。
> 配套材料：TS × React 专题的深度思考见《技术思考：从 TS 模块隔离到 Hooks 类型设计》（同目录，作为该专题的展开教材）。

---

## 一、方案定位

### 1.1 适用对象与周期

- **适用对象**：0~1 年经验的前端新同学（应届、校招、初级社招），具备 HTML/CSS/JS 基础；
- **培养周期**：12 个月四阶段（密集培养可压缩至 6 个月，见第十一章弹性调整）；
- **培养终局**：独立负责业务模块与一次架构级改造，通过结业答辩。

### 1.2 高级全栈前端的能力边界（先说清楚"全栈"指什么）

本方案的"全栈"指：

1. **客户端纵深**：浏览器原理、渲染机制、网络协议、性能与安全的底层理解；
2. **框架与类型**：React 生态 + TypeScript 类型系统 + 状态管理的设计能力；
3. **服务端延伸**：Node.js / BFF 中间层、数据库基础、接口设计与部署运维；
4. **工程与架构**：构建工具链、CI/CD、监控、测试、微前端等架构级手段；
5. **AI 应用与 Agent 开发**：把大模型能力工程化地融入前端产品——提示词工程、工具调用、Agent 编排、RAG 检索与流式 UI；
6. **业务与软素质**：需求拆解、独立交付、技术分享、带人与 review。

不要求：精通后端开发、运维专家、DBA——那些是"能协作、能理解"，不是"能替代"。

### 1.3 培养理念

1. **全栈视野，单点打透**：每个能力域都过一遍建立全局观，在其中 1~2 个域（本方案选类型系统与工程化）打穿到能讲原理；
2. **实战主线**：所有知识在真实项目场景中习得，每月有产物；
3. **以产物验收**：考核看代码、文档、演示，不看口头汇报；
4. **诚实定位**：12 个月建立高级档位的完整能力框架与实战底座，真实职级认证仍需后续历练——方案第十章写清这段差距。

## 四、阶段一：语言与计算机基础（第 1~3 月）

**阶段目标**：语言基础与底层原理一次打牢；看懂类型报错；能讲清浏览器渲染、事件循环、HTTP 基本原理；工程规范一步到位。

### 月度计划

**月 1：HTML/CSS/JS 深入 + 环境规范**

- 学习：
  - 现代 CSS：Flex/Grid 布局体系、层叠上下文、BFC、响应式方案、CSS 工程化（CSS Modules / Tailwind 选型）；
  - JavaScript 深入：闭包、原型链、this、事件循环（宏/微任务）、Promise/async、ES2020+ 新特性；
  - 第 0 周规范：Git 协作（Conventional Commits、PR 粒度）、ESLint/Prettier/husky 工具链；
- 动手：T0 规范任务；JS 基础任务集（8 个：手写防抖节流、深拷贝、Promise 并发控制、事件循环输出题等）；
- 验收：给一段含宏微任务的代码能正确写出输出顺序；规范 PR 合入。

**月 2：TypeScript 类型系统**

- 学习：TS 核心（interface/type、联合类型、类型收窄、泛型与约束、类型推导）、模块隔离与 `export {}`、Hooks 类型设计五原则（详细展开见配套思考文档《技术思考：从 TS 模块隔离到 Hooks 类型设计》）；
- 动手：TS 任务集（标注取舍判断、布尔堆重构为联合类型、泛型 Hook 编写、type-challenges 简单+中等各 5 题）；
- 验收：原理 12 问之 TS 部分（模块机制、any vs unknown、类型收窄的三种手段）全部通过导师抽问。

**月 3：浏览器原理与网络基础**

- 学习：
  - 浏览器：渲染流水线（解析→样式→布局→绘制→合成）、重排重绘、合成层、事件循环与页面、缓存策略；
  - 网络：HTTP/1.1~3 演进、HTTPS/TLS 握手、强缓存与协商缓存、Cookie/Session/Token、DNS 与 CDN 原理、跨域方案全景（CORS/代理/WebSocket）；
- 动手：浏览器任务集（用 Performance 面板分析一次重排、手写一个带缓存的 fetch 封装、抓包分析一次完整请求）；
- 验收：原理 12 问之浏览器与网络部分；给一个"页面白屏"场景能列出系统的排查路径。

**阶段一产出与考核**：原理 12 问（语言/TS/浏览器/网络四域）通过；基础任务集全部通过；月度考核表见第十章。

## 五、阶段二：框架与业务实战（第 4~6 月）

**阶段目标**：吃透 React 体系与状态管理；独立完成一个完整中后台项目；建立"类型从哪来、状态放哪里、请求怎么封"的完整闭环；测试入门。

### 月度计划

**月 4：React 体系**

- 学习：
  - React 原理：Fiber 架构概览、 reconciliation 与 diff 策略、Hooks 实现机制（为什么不能条件调用）、受控与非受控；
  - React 生态：React Router 路由设计、组件设计模式（组合 vs 继承、render props、HOC 的时代与 Hook 化）、antd 等 UI 库的定制体系；
- 动手：实现一个迷你 hooks 库（useDebounce/useThrottle/usePrevious），用类型约束到位；
- 验收：讲清"Hooks 为什么要依赖数组""受控组件的性能代价与替代方案"。

**月 5：状态管理 + 请求层 + 业务实战项目启动**

- 学习：zustand 与 TanStack Query 的分工（客户端状态 vs 服务端状态）、请求封装与防竞态、antd CRUD 全套、表单层级建模、ECharts 数据与配置分离；
- 动手：**项目一（中后台管理系统）**启动——抓包建型（json2ts + 类型守卫/zod 兜底）、目录分层（types/ vs domain/ 归位规则）、登录模块（zustand）、用户管理页；
- 验收：新接口 30 分钟内完成建型到调用，无 `any` 逃生门（操作细节见配套思考文档第六节）。

**月 6：项目收尾 + 测试入门 + 月度考核**

- 学习：测试金字塔（Vitest 单测、React Testing Library 组件测试、Playwright E2E 入门）、测试该测什么不该测什么；
- 动手：项目一补齐测试（请求层、登录态、复杂表单）、ECharts 图表页、系统设置页；部署到测试环境；
- 验收：项目一完整可运行、核心逻辑测试覆盖；月度考核表通过。

## 六、阶段三：全栈与工程体系（第 7~10 月）

**阶段目标**：打通服务端延伸（Node/BFF/数据库/部署）与工程化体系（构建/CI/监控/性能/安全/AI Agent），成为能独立交付完整链路的"全栈前端"。

### 月度计划

**月 7：Node.js 与 BFF 中间层**

- 学习：
  - Node 基础：事件循环（与浏览器差异）、Stream、模块系统；框架二选一（Express/Koa/NestJS，建议 NestJS——依赖注入与装饰器对 TS 类型友好）；
  - BFF 模式：接口聚合、数据裁剪、鉴权网关；RESTful 设计与 OpenAPI 文档先行；
  - 数据库基础：MySQL 基本增删改查、Redis 缓存思路（能看懂慢查询、能写简单聚合即可，不追求 DBA 深度）；
- 动手：**项目二（全栈 BFF 项目）**启动：为项目一的页面补一层 BFF（聚合两个上游接口 + 鉴权 + 日志）；
- 验收：BFF 层有完整的类型定义（DTO 贯通前后端）、接口有文档、有鉴权与错误码规范。

**月 8：工程化与质量保障**

- 学习：
  - 构建工具链：Vite/Webpack 原理概览、插件与 loader 机制、按需加载与代码分割、Monorepo（pnpm workspace）与包管理；
  - CI/CD：GitHub Actions/GitLab CI 流水线设计（lint → test → build → deploy）、环境管理（dev/staging/prod）；
  - 监控：前端错误监控（Sentry 思路、错误上报方案）、性能指标采集（Web Vitals）、日志规范；
- 动手：为项目一/二搭建完整流水线 + 接入错误监控 + 一条真实线上问题的"发现→定位→修复"演练；
- 验收：从提 PR 到测试环境部署全自动；模拟一个运行时错误，能通过监控日志 5 分钟内定位到代码行。

**月 9：性能优化 + 安全防护 + 月度考核**

- 学习：
  - 性能：加载性能（首屏、懒加载、资源优化、HTTP 缓存实战）、运行时性能（长列表虚拟滚动、memo 语义、内存泄漏排查）、Web Vitals 指标体系；
  - 安全：XSS（存储/反射型与转义策略）、CSRF（token 与 SameSite）、CSP、同源策略与越权、依赖审计（npm audit/lockfile 安全）；
- 动手：**性能专项**——对项目一做一轮优化并输出前后数据（LCP/TTI/包体积）；**安全专项**——在演练环境中复现并修复一个 XSS 与一个 CSRF 漏洞；
- 验收：性能报告有数据有归因；安全演练能讲清攻击路径与修复原理；月度考核表通过。

**月 10：AI 与 Agent 开发专项**

- 学习：
  - LLM 应用基础：模型 API 调用、token 与上下文窗口、流式响应（SSE）、function calling / tool use；
  - 提示词工程：系统提示词设计、结构化输出（JSON Schema）、少样本示例、幻觉抑制与降级策略；
  - Agent 架构：ReAct 循环、工具调用与工具的类型定义、MCP（Model Context Protocol）接入、多 Agent 协作概览；
  - RAG 基础：embedding 与向量检索、召回与重排、前端集成（聊天 UI、流式渲染、打字机效果、中断与重试）；
  - AI 研发提效：AI 辅助 code review、智能表单 / Copilot 侧边栏等前端 AI 场景；
- 动手：**项目三（AI Agent）**——为项目二加一个 AI 助手：自然语言查数据 → 工具调用 → 流式回答；或做一个接入 MCP 的前端研发 Agent（如"用一句话生成查询报表"）；
- 验收：流式 UI 可用且可中断、可重试；每个工具调用有类型定义与错误兜底；能完整演示一条 Agent 任务链，并讲清"Agent 和普通接口调用"的本质区别（自主决策循环 vs 固定调用链）。

## 七、阶段四：架构设计与职级认证（第 11~12 月）

**阶段目标**：从"交付功能"升级到"设计系统"——主导一次架构级改造，通过原理深问与结业答辩完成职级检验。

### 月度计划

**月 11：架构设计能力 + 模块负责制启动**

- 学习：
  - 组件架构：组件粒度设计、容器/展示分离的现代形态、设计系统思路（tokens/主题）；
  - 状态架构：三层模型（DTO / 领域模型 / 视图模型）、大型项目类型系统设计（strict 约束、统一出口、演进策略）；
  - 微前端与模块联邦：适用场景、隔离方案（样式/JS/状态）、渐进式迁移策略；路由级拆分与依赖治理；
- 动手（架构）：为项目二写一份《架构演进方案》（现状问题 → 目标架构 → 迁移路径 → 风险预案），导师评审；
- 动手（实战）：接手一个真实业务模块，导师只做顾问：需求评审发言 → 技术方案文档 → 排期与风险暴露；
- 验收：架构方案通过评审，能回答"为什么这样拆、不拆会怎样、迁移期间怎么保证线上稳定"。

**月 12：模块交付与结业答辩**

- 模块交付：完成模块的开发、测试、上线与复盘；方案必须含备选方案与回滚预案，**主动暴露风险比"不出问题"更重要**；同时完成原理 12 问全部抽问（语言/TS/浏览器/网络/框架/工程六域各 2 问）；
- 结业答辩：30 分钟技术分享（面向全组，主题自选，建议讲模块负责中的真实架构决策或 AI Agent 落地实践）+ 15 分钟问答 + 1 份 ASCII 手绘的**全栈知识体系导图**（自己画，不许抄）；
- 评审：导师 + 一名组内资深前端 + 技术负责人；
- 通过标准：见第十章评分表（≥ 75 分）；
- 未通过：给出补齐项，一个月后二次答辩。

| 机制 | 频率 | 内容 |
|------|------|------|
| **1v1 沟通** | 每周 30 分钟 | 进度同步、卡点排查；学员带"本周三件事"，导师带"下周一个挑战" |
| **代码 Review** | 每个 PR | 导师 review 学员全部 PR；月 6 起反向演练——学员 review 导师的 PR 并提意见 |
| **双周技术复盘** | 每两周 | 学员讲一个"本周踩的坑"（5 分钟），全组讨论 |
| **月度考核** | 每月末 | 按第十章评估表逐项验收，双签归档 |
| **挑战任务** | 不定期 | 投放"跳一跳够得着"的加餐题（手写 hooks 库、阅读 Vite 插件源码等） |

**带教红线**：不直接给答案，先指踩坑提示；考核不放水，产物是唯一尺子；学员连续两周无进展，先排查任务设计问题，不默认学员不努力。

## 十、考核评估体系

### 10.1 月度里程碑考核（导师用，逐月双签）

| 月份 | 阶段 | 核心考核项 | 验收标准 |
|------|------|-----------|----------|
| 月 1 | 基础 | JS 任务集 + 规范 PR | 事件循环输出题全对；commit 历史符合规范 |
| 月 2 | 基础 | TS 任务集 + 原理抽问 | 泛型 Hook 独立写出；TS 部分原理 12 问通过 |
| 月 3 | 基础 | 浏览器/网络任务集 | 白屏排查路径完整；HTTPS 握手讲清 |
| 月 4~6 | 框架 | 项目一交付 + 测试 | 项目可运行、无 any 逃生门、核心逻辑有测试 |
| 月 7~10 | 全栈 | 项目二 + 流水线 + 性能安全 + AI Agent 专项 | BFF 贯通、监控可用、性能报告有数据、安全演练完成、AI Agent 项目可完整演示 |
| 月 11~12 | 架构 | 架构方案 + 模块负责 + 答辩 | 方案过评审、模块闭环上线、答辩 ≥ 75 分 |

> 各项的详细验收标准随月度计划分布在四~七章，正式表格由导师按月填写归档到 `handbook-notes/<学员>/`，作为转正/定级参考。

### 10.2 结业答辩评分表（总分 100，≥ 75 通过）

| 维度 | 权重 | 评分要点 |
|------|------|----------|
| 技术深度 | 35 | 原理 12 问抽问；至少一个能力域（建议类型系统或工程化）能讲到"为什么"并经得起三层追问 |
| 全栈交付 | 30 | 模块负责闭环完整；BFF/部署/监控链路是自己搭的且讲得清；AI Agent 功能可完整演示 |
| 架构能力 | 20 | 架构演进方案的取舍合理；迁移路径可执行、风险有预案 |
| 软素质 | 15 | 分享表达清晰、问答互动有质量、review 意见有据 |

### 10.3 培养效果回访（结业 3 个月后）

结业不是终点：导师回访学员独立交付模块的稳定性、是否带过更初级同学、四维能力是否守住达标线；回访结论用于迭代本方案。

## 十一、弹性调整机制

- **6 个月加速版**：适合基础较好的社招同学——阶段一压缩为 1 个月（只保留 TS 与规范），阶段二 2 个月，阶段三 2 个月，阶段四 1 个月；砍掉 E2E 与安全演练，**AI Agent 专项压缩为两周的项目实战（不砍）**，保留主线项目与答辩；
- **按背景裁剪**：后端转前端者阶段一补 React，阶段三的 BFF 与数据库可提前；实习生长周期版本为 18 个月（月 1~12 全流程 + 6 个月真实业务历练）；
- **进度落后处理**：落后 1 周加练；落后 2 周共同归因并砍支线（保类型系统与项目闭环两条主线）；落后 1 个月整体延后一阶段，培养周期顺延；
- **方案迭代**：每期培养结束，导师复盘考核数据与学员反馈，更新月度计划与评分标准。
