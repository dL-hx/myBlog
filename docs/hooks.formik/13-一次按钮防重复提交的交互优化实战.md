# 实战：按钮防重复提交的两个落地方案（Hook 封装 + 单组件内联）

关键词：防重复提交、状态锁、useRef、节流冷却、最小 loading、try/finally、自定义 Hook

> 本文是《从「状态锁」到「节流 + 状态锁」：一次按钮防重复提交的交互优化复盘》的实战篇：不再讲原理演进，直接给出两套可以复制进项目的落地代码。

## 一、目标：两条硬性约束

无论用哪个方案，都必须同时保证：

1. **请求进行中不重复提交**：极速连点、慢请求期间的重入全部拦截，只发 1 次。
2. **请求成功后解锁**：loading 结束后释放状态锁，不设「已提交」永久锁，用户可以再次点击提交。

附带两条体验兜底：

- **失败也解锁**：finally 保证异常路径不会把按钮永久锁死，用户可重试。
- **最小 loading 时长**：接口太快时 loading 不闪烁，成功失败两条路径都补时。

## 二、方案一：用 Hook（推荐，可复用）

### 2.1 Hook 实现

```tsx
// useSubmitAction.ts
import { useCallback, useEffect, useRef, useState } from 'react';

const sleep = (ms: number) => new Promise<void>((r) => setTimeout(r, ms));

type RejectReason = 'running' | 'cooldown';

interface Options {
  /** 冷却时间，默认 1000ms；设为 0 表示请求结束即可再点 */
  cooldown?: number;
  /** loading 最小展示时长，默认 300ms */
  minLoadingTime?: number;
  onReject?: (reason: RejectReason) => void;
}

export function useSubmitAction<T extends (...args: any[]) => Promise<any>>(
  action: T,
  { cooldown = 1000, minLoadingTime = 300, onReject }: Options = {}
) {
  const [loading, setLoading] = useState(false);
  const runningRef = useRef(false);   // 状态锁
  const lastTimeRef = useRef(0);      // 节流
  const mountedRef = useRef(true);
  const actionRef = useRef(action);
  const onRejectRef = useRef(onReject);

  useEffect(() => { actionRef.current = action; });
  useEffect(() => { onRejectRef.current = onReject; });

  useEffect(() => {
    mountedRef.current = true;
    return () => { mountedRef.current = false; };
  }, []);

  const run = useCallback(async (...args: Parameters<T>) => {
    // 1. 请求进行中，拦截
    if (runningRef.current) {
      onRejectRef.current?.('running');
      return;
    }
    // 2. 冷却窗口内，拦截
    const now = Date.now();
    if (now - lastTimeRef.current < cooldown) {
      onRejectRef.current?.('cooldown');
      return;
    }

    runningRef.current = true;
    lastTimeRef.current = now;
    if (mountedRef.current) setLoading(true);

    const start = Date.now();
    try {
      return await actionRef.current(...args);
    } finally {
      // 3. 补足最小 loading 时长
      const rest = minLoadingTime - (Date.now() - start);
      if (rest > 0) await sleep(rest);
      // 4. 解锁：成功、失败都解锁，成功后可以再次点击
      runningRef.current = false;
      if (mountedRef.current) setLoading(false);
    }
  }, [cooldown, minLoadingTime]);

  return { run, loading };
}
```

### 2.2 业务中使用

```tsx
import { useSubmitAction } from './useSubmitAction';

function SubmitForm() {
  const { run, loading } = useSubmitAction(
    async (payload: { name: string }) => {
      const res = await fetch('/api/submit', {
        method: 'POST',
        body: JSON.stringify(payload),
      });
      if (!res.ok) throw new Error('提交失败');
      return res.json();
    },
    {
      cooldown: 1000,
      minLoadingTime: 300,
      onReject: (reason) => {
        if (reason === 'cooldown') message.info('操作太频繁，请稍后再试');
      },
    }
  );

  return (
    <button onClick={() => run({ name: 'test' })} disabled={loading}>
      {loading ? '提交中...' : '提交'}
    </button>
  );
}
```

### 2.3 行为清单

- 请求进行中再点：拦截，只发 1 次。
- 请求成功 → loading 结束 → 冷却 1s 后解锁，可再次提交。
- 请求失败 → finally 同样解锁，可立即重试（若不想立刻重试，失败也走冷却）。
- 若希望成功后立刻可再点，把 cooldown 设为 0。

### 2.4 实现要点

- **锁放 ref 不放 state**：`runningRef.current` 是同步读写的实时值；`loading` state 是渲染快照，同一事件循环里读不到最新值，拦不住极速连点。
- **action 用 actionRef 保持最新**：`run` 的依赖数组里只有 `cooldown` 和 `minLoadingTime`，回调引用稳定，不会因 action 变化而失效，也规避了闭包陷阱。
- **解锁写在 finally**：成功、失败、抛错三条路径都会走到解锁逻辑，按钮永远不会被永久禁用。
- **冷却语义**：冷却窗口从「本次触发时刻」开始计算。若请求耗时超过 cooldown，请求结束后可立即再次触发；若要求「请求结束后再冷却」，在 finally 中把 `lastTimeRef.current` 更新为 `Date.now()`。

## 三、方案二：不用 Hook（单组件内联实现）

适合只有一个提交按钮、不想抽 Hook 的场景。

```tsx
import { useRef, useState, useEffect } from 'react';

const sleep = (ms: number) => new Promise<void>((r) => setTimeout(r, ms));

function SubmitForm() {
  const [loading, setLoading] = useState(false);
  const runningRef = useRef(false);   // 状态锁
  const lastTimeRef = useRef(0);      // 节流
  const mountedRef = useRef(true);

  useEffect(() => {
    mountedRef.current = true;
    return () => { mountedRef.current = false; };
  }, []);

  const handleSubmit = async (payload: { name: string }) => {
    const COOLDOWN = 1000;
    const MIN_LOADING = 300;

    // 1. 状态锁：请求进行中，拦截
    if (runningRef.current) return;

    // 2. 节流：冷却窗口内，拦截
    const now = Date.now();
    if (now - lastTimeRef.current < COOLDOWN) {
      message.info('操作太频繁，请稍后再试');
      return;
    }

    runningRef.current = true;
    lastTimeRef.current = now;
    setLoading(true);

    const start = Date.now();
    try {
      const res = await fetch('/api/submit', {
        method: 'POST',
        body: JSON.stringify(payload),
      });
      if (!res.ok) throw new Error('提交失败');
      const data = await res.json();
      // 成功后可以做业务跳转/提示，但锁照样在 finally 释放，可再次提交
      message.success('提交成功');
      return data;
    } catch (e) {
      message.error((e as Error).message);
      throw e;
    } finally {
      // 3. 补足最小 loading 时长
      const rest = MIN_LOADING - (Date.now() - start);
      if (rest > 0) await sleep(rest);
      // 4. 解锁：成功、失败都解锁
      runningRef.current = false;
      if (mountedRef.current) setLoading(false);
    }
  };

  return (
    <button onClick={() => handleSubmit({ name: 'test' })} disabled={loading}>
      {loading ? '提交中...' : '提交'}
    </button>
  );
}
```

## 四、两个方案的区别

| 维度 | Hook 方案 | 内联方案 |
| --- | --- | --- |
| 复用性 | 多个按钮共用 | 每个组件复制 |
| 闭包安全 | actionRef 保持最新 | 组件内函数天然是最新 |
| 卸载保护 | mountedRef | mountedRef |
| 代码量 | 一次封装，多次使用 | 单处更短 |
| 适合 | 项目里多处提交 | 只有一个按钮的简单页 |

## 五、关键点速记

- 成功后要能再点：finally 里只释放 runningRef，不设置「已提交」永久锁。
- 请求进行中只发一次：靠 runningRef.current 同步判断，不能用 loading state（闭包快照拦不住极速连点）。
- 冷却可选：想要「成功后立刻可再点」，cooldown 设 0；想要「成功后 1 秒内不许再点」，保留 1000。
- 失败也解锁：finally 保证异常路径不会把按钮永久锁死。
- 最小 loading：在 finally 里补时，成功失败都不会闪。

## 六、验收清单

上线前拿这套用例过一遍：

| 用例 | 预期 |
| --- | --- |
| 请求进行中极速连点 5 次 | 只发 1 次请求 |
| 请求成功后等 loading 结束 | 按钮恢复可点，可再次提交 |
| 请求成功后 1s 内再点 | 被 cooldown 拦截，toast 提示「操作太频繁」 |
| 接口返回 500 / 断网 | loading 结束、按钮解锁，可重试 |
| 接口 30ms 秒回 | loading 至少展示 300ms，不闪烁 |
| 提交中切换页面（组件卸载） | 无 setState 报错，无内存泄漏 |
