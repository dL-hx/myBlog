# 事件委托：目标定位与 React/Vue 实战

::: tip 一句话导读
除了 `closest`，事件委托里定位目标元素还有几种常用手段，各有适用场景。
在 React/Vue 时代，这项技术不仅没有过时，反而以更底层的机制（合成事件）支撑着框架的性能；
在特定场景下，手动使用事件委托依然是重要的优化和解决问题的方式。
:::

## 📌 技术点速览

| 序号 | 技术点 | 一句话理解 |
|---|---|---|
| 1 | 定位目标元素的 4 种手段 | `closest` 向上找、`matches` 判自身、`dataset` 存意图、`currentTarget` 指容器 |
| 2 | 复杂嵌套结构的分层定位 | 先定位区域，再判明意图 |
| 3 | 适时 `stopPropagation()` | 防止多层委托重复捕获 |
| 4 | `pointer-events: none` | 让装饰元素不接收指针事件 |
| 5 | 框架内部的事件委托 | React 合成事件在根节点统一注册 |
| 6 | 开发者手中的事件委托 | 长列表、第三方 DOM、高频事件三处不可替代 |

## 🎯 技术点 1：除了 `closest`，还有哪些取元素的方式？

`closest` 擅长处理「点击了子元素（如图标），但需要找到其父级语义容器（如按钮）」的场景。
其他方式各有侧重。

### 四种方式速查

| 方式 | 返回值 | 查找方向 | 适用场景 | 记忆口诀 |
|---|---|---|---|---|
| `e.target.closest(sel)` | Element \| null | **向上**找祖先 | 点中子元素要找到最近的可操作容器 | 「往上找最近的可操作节点」 |
| `e.target.matches(sel)` | Boolean | **只看自身** | 结构扁平、无需追溯父级 | 「就问自己是不是」 |
| `el.dataset.action` | String | 读属性 | 配合 `closest('[data-action]')` 标识意图 | 「用属性存指令，别用 class」 |
| `e.currentTarget` | Element | 固定指向 | 始终是绑定监听器的委托容器 | 「谁绑的监听就是谁」 |

### ① `closest` —— 向上找最近的可操作节点（最常用）

```js
container.addEventListener('click', (e) => {
  // 点击的是 <svg> 或 <span>，向上找到最近的按钮
  const btn = e.target.closest('[data-action]');
  if (!btn) return;
  console.log(btn.dataset.action);
});
```

**要点**：从自身开始向上查找，命中第一个匹配元素就返回。穿透子元素最方便。

### ② `matches` —— 精确判断自身是否匹配

```js
container.addEventListener('click', (e) => {
  if (e.target.matches('.list-item')) {
    // 只有点中 li 本身才处理
    console.log('直接点中了列表项');
  }
  // ❌ 点击 li 内部的 <span> 时不会触发
});
```

**要点**：不向上查找，只判断 `e.target` 自身。适合结构扁平、层级固定、不需要穿透子元素的场景。

### ③ `dataset` —— 用 `data-*` 标识意图（推荐组合用法）

```html
<button data-action="delete">删除</button>
```

```js
const actionEl = e.target.closest('[data-action]');
const action = actionEl?.dataset.action; // "delete"
```

::: tip 为什么比匹配 class 更好
- **语义明确**：`data-action` 一眼看出是「指令」，`.btn-red` 是「样式」
- **不跟样式耦合**：改样式不会误伤逻辑
- **一次定位**：`closest('[data-action]')` 直接找到可操作节点，不用逐层判断
:::

### ④ `currentTarget` —— 永远指向委托容器

```js
listEl.addEventListener('click', (e) => {
  console.log(e.target);        // 实际点中的元素（可能是深层子节点）
  console.log(e.currentTarget); // 永远是 listEl（绑定监听器的那个）
});
```

**要点**：需要明确操作「容器本身」时用它，比如判断点击是否落在容器外。

## 🧩 技术点 2：复杂嵌套结构 —— 分层定位

复杂结构（如列表项内嵌套多个操作按钮）容易导致**误触**或**重复处理**。
核心思路：**先定位区域，再判明意图**。

```
click 事件冒泡到容器
  └─ 第一层：closest 定位到语义单元（.list-item）
       └─ 第二层：单元内 closest 配合 data-action 判明行为
            └─ 读取 dataset.action 分发
```

```js
container.addEventListener('click', (e) => {
  // 第一层：定位到最内层的语义单元
  const itemEl = e.target.closest('.list-item');
  if (!itemEl) return;

  // 第二层：在这个单元内部判断具体行为
  const actionEl = e.target.closest('[data-action]');
  if (!actionEl || !itemEl.contains(actionEl)) return;

  const { action } = actionEl.dataset;
  const id = itemEl.dataset.id;
  // 分发...
});
```

::: tip 分层的好处
- 避免「全局比对」：只在命中的单元内继续判断
- 天然防止跨项误触：`itemEl.contains(actionEl)` 确保按钮属于当前项
- 逻辑可读：区域 → 意图两级结构，比一大坨 `if` 清晰
:::

## 🚧 技术点 3：适时 `stopPropagation()`

完成一次委托处理后，如果希望事件**不再向上冒泡**触发外层的同类委托
（例如嵌套列表或卡片），可以调用 `e.stopPropagation()` 终止传播。

```js
// 嵌套场景：卡片里套列表，列表里套按钮，三层都做了委托
cardEl.addEventListener('click', handleCardClick);
listEl.addEventListener('click', handleListClick);
btnEl.addEventListener('click', handleBtnClick);

function handleBtnClick(e) {
  // 按钮的行为处理完，不希望再触发 list 和 card 的委托
  e.stopPropagation();
}
```

::: warning 注意
只在**确实需要截断**时调用。滥用会导致外层埋点、点击外部关闭等逻辑失效。
:::

## 🖱️ 技术点 4：`pointer-events: none` 让装饰元素透明

对于纯装饰性的子元素（如图标），可以通过 CSS 让其不接收指针事件，
这样 `event.target` 会**直接落到真正有意义的可点击父级**上，简化逻辑。

```css
.action-btn svg,
.action-btn .icon {
  pointer-events: none; /* 图标不接收指针事件 */
}
```

```js
// 这样 e.target 直接就是 button，不需要 closest 穿透图标
if (e.target.matches('[data-action]')) { /* ... */ }
```

| 方案 | 优点 | 代价 |
|---|---|---|
| `pointer-events: none` | `e.target` 直接命中，逻辑最简 | 纯 CSS 约束，图标上的独立交互会失效 |
| `closest` 穿透 | 灵活，不侵入样式 | 每次点击有遍历开销 |

## ⚛️ 技术点 5：框架内部 —— 事件委托是性能基石

React 和 Vue 自身就**重度依赖事件委托**来保证性能。

```
传统逐元素绑定                  React 合成事件
─────────────                  ──────────────
div 1 → listener 1              所有节点
div 2 → listener 2                 ↓
...                               根容器（1 个监听器）
div N → listener N                 ↓
                             按虚拟 DOM 树分发
```

- **React 合成事件系统**：并非为每个元素单独绑定监听器，而是在**根节点（React 17+ 为根容器）** 上统一注册所有事件，然后通过虚拟 DOM 树分发到具体的组件处理器。这在大型列表中能**减少超过 90% 的事件绑定**，显著节省内存。
- **Vue 的 `v-on`** 在底层同样利用了事件委托来优化性能。

::: warning 作用域差异（容易踩坑）
React 合成事件的 `e.stopPropagation()` 阻止的是**虚拟 DOM 树**上的传播，而非原生 DOM 事件传播，两者作用域不同。

- 在 React 组件里调 `e.stopPropagation()`，**不会**阻止一个挂在 `document` 上的原生监听器
- 混用原生监听器与合成事件时，要清楚自己在哪一层拦截
:::

## 🛠️ 技术点 6：开发者手中 —— 解决特定问题的利器

在框架之上，手动使用事件委托依然不可替代：

### ① 处理大规模动态列表

列表项数量极多或频繁增删时，在父容器上使用**一个原生事件监听器**（通过 `ref` 绑定），
比给每个子项都挂一个 React `onClick`，在极端场景下能获得更直接的内存和性能优势。

### ② 与非受控 / 第三方 DOM 交互

需要监听由**第三方库（富文本编辑器、图表库）动态生成的内部元素**时，
由于无法直接在其 React 组件上挂载事件，在稳定的父容器上进行事件委托是标准解决方案。

### ③ 优化高频事件

对于 `scroll`、`mousemove` 等高频事件，在父级**统一监听并结合防抖/节流**，
比在多个子元素上分散监听更易于管理。

## 💻 实战 React 代码：手动事件委托优化长列表

以下示例展示了在一个包含大量按钮的列表中，如何通过父容器的**一个原生事件监听器**统一处理所有点击，
利用 `data-action` 和 `closest` 进行委托分发。

```jsx
import React, { useEffect, useRef, useState } from 'react';

// 模拟一个包含大量操作按钮的列表项组件
const ListItem = React.memo(({ item }) => {
  return (
    <li className="list-item" data-id={item.id}>
      <span className="item-name">{item.name}</span>
      {/* 注意：这里没有绑定任何 onClick，事件交由父容器统一处理 */}
      <button className="action-btn" data-action="edit">编辑</button>
      <button className="action-btn" data-action="delete">删除</button>
    </li>
  );
});

export default function DelegatedList({ items }) {
  const listRef = useRef(null);
  const [message, setMessage] = useState('');

  useEffect(() => {
    const container = listRef.current;
    if (!container) return;

    // 核心：在父容器（ul）上绑定一个原生 click 监听器
    const handleClick = (e) => {
      // 1. 使用 closest 向上查找最近的可操作按钮，穿透子元素（如图标）
      const actionEl = e.target.closest('[data-action]');
      if (!actionEl) return; // 点击的是非操作区域，忽略

      // 2. 读取 data-* 属性，获取具体指令
      const action = actionEl.dataset.action;

      // 3. 继续向上找到所属的列表项，获取业务 ID
      const itemEl = actionEl.closest('[data-id]');
      const itemId = itemEl?.dataset.id;

      // 4. 执行分发逻辑
      if (action === 'edit') {
        setMessage(`编辑项目: ${itemId}`);
      } else if (action === 'delete') {
        setMessage(`删除项目: ${itemId}`);
        // 实际场景中会在此调用 setState 或 API
      }

      // 5. 阻止冒泡，避免触发外层可能存在的其他同类型委托
      e.stopPropagation();
    };

    container.addEventListener('click', handleClick);
    // 清理函数：组件卸载时移除监听器
    return () => container.removeEventListener('click', handleClick);
  }, []); // 空依赖数组，确保只绑定一次

  return (
    <div>
      {message && <p style={{ color: 'green' }}>{message}</p>}
      <ul ref={listRef} style={{ listStyle: 'none', padding: 0 }}>
        {items.map((item) => (
          <ListItem key={item.id} item={item} />
        ))}
      </ul>
    </div>
  );
}
```

### 逐行拆解：5 个关键动作

| 步骤 | 代码 | 作用 |
|---|---|---|
| ① | `e.target.closest('[data-action]')` | 穿透图标等子元素，找到可操作按钮 |
| ② | `actionEl.dataset.action` | 读取指令，决定分发到哪个分支 |
| ③ | `actionEl.closest('[data-id]')` | 向上找所属列表项，拿到业务 ID |
| ④ | `if / else` 分发 | 集中处理所有行为 |
| ⑤ | `e.stopPropagation()` | 防止事件继续冒泡触发外层同类委托 |

### 这个例子体现了什么

| 优势 | 说明 |
|---|---|
| **性能** | 无论列表有 10 项还是 1000 项，都只存在**一个**原生事件监听器 |
| **动态性** | `ListItem` 通过 `React.memo` 优化，且**自身不携带事件处理器**，列表项增删改不会引发事件系统的额外绑定/解绑开销 |
| **逻辑清晰** | 所有点击行为的判断与分发逻辑**集中在父组件一处**，易于维护 |

## ✅ 技术点回顾

::: tip 三句话记住这篇
1. **定位手段不止 `closest`**：`matches` 判自身、`dataset` 存意图、`currentTarget` 指容器。
2. **复杂结构靠分层**：先定位区域 → 再判明意图 → 必要时截断冒泡。
3. **框架时代依然有用**：框架内部靠它做性能基石，开发者手上靠它接第三方 DOM、治高频事件、稳长列表渲染。
:::

::: warning 最容易踩的坑
React 合成事件的 `e.stopPropagation()` 只作用于虚拟 DOM 树，**不会**阻止 `document` 上的原生监听器。
混用两种事件体系时，务必清楚自己在哪一层拦截。
:::
